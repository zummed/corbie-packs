Bot project: you make a project directory for a bot that answers people on Telegram, Slack, GitLab and Jira, and change the bot by changing its files.

The packs are ready-made Corbie machines. `corbie add` writes each pack
into the project's `.packs/`, and writes its starting files, which place the
bot's calls with files of one line. The project's own files say where each
message goes, who someone is, and what each agent can do.

  bot                              the conversation, the lookup, the approval and the question
  slack, telegram, gitlab, jira    a service's listener and calls
  shared                           scripts the others use; corbie add writes it with them

Start a project
---------------

1. Start Corbie, and in the project's directory add the pack `bot` and the pack of each service, with the bot's name as `--set BOT=<name>`.
2. For Slack, make the app first, as The Slack app below says.
3. Add the agent, as Add an agent below says, and set each service's secrets and values.
4. Submit the project.

    corbie init --ceiling all
    corbie start controller runner ui &
    mkdir my-bot && cd my-bot
    corbie add github.com/zummed/corbie-packs/bot github.com/zummed/corbie-packs/slack --set BOT=grouse
      .packs/bot     github.com/zummed/corbie-packs/bot  <commit>
      .packs/shared  needed by bot  <commit>
      .packs/slack   github.com/zummed/corbie-packs/slack  <commit>
      .packs/shared  needed by slack  <commit>

      Wrote these starting files:

        .corbieignore
        .mcp.json
        AGENTS.md
        CLAUDE.md
        answers.yaml
        ballot.yaml
        conversation.yaml
        later.yaml
        people/find.yaml
        people/scopes.yaml
        grouse/slack/assistant/status.yaml
        grouse/slack/chat/ask.yaml
        grouse/slack/chat/post.yaml
        grouse/slack/chat/show.yaml
        grouse/slack/files/get.yaml
        grouse/slack/grouse.yaml

      Then: corbie test .

    corbie client secret set SLACK_TOKEN --at /my-bot/grouse/slack
    corbie client secret set SLACK_APP_TOKEN --at /my-bot/grouse/slack
    corbie run submit .

`corbie add` writes `grouse` in place of `BOT` in each starting file's path
and text. It takes `--in <directory>` for a project that is not the current
directory, a directory on this computer as a pack, and a tag, branch or
commit after a pack, as `github.com/zummed/corbie-packs/slack@v0.8.0`.

Each service's secrets and values are set at `/my-bot/grouse/<service>`, a
secret with `corbie client secret set <NAME> --at` and a value with `corbie
client value set <NAME> <value> --at`:

  telegram    the secret TELEGRAM_TOKEN
  slack       the secrets SLACK_TOKEN and SLACK_APP_TOKEN
  gitlab      the secret GITLAB_TOKEN, and the value GITLAB_SITE
  jira        the secret JIRA_TOKEN, and the values JIRA_SITE and JIRA_EMAIL

`corbie run submit .` records the project as the tree `/my-bot`, and starts
each router, which starts its listener. A secret or a value set at
`/my-bot/grouse/slack` is used by the Slack router and calls of the bot
`grouse`, and one set at `/my-bot` by every run of the project. Set each at
the narrowest location.

- Until the project has an agent, the bot answers anyone who names it with `This bot has no agent yet.`
- Submit the project from a client no gateway uses: a gateway whose client submitted the project can call any of its locations with any input.
- `corbie ui` shows each run and what waits on a person. Its Toolkits page shows each toolkit, the agents that offer it, and which of its tools have `approve: true`.

After a change
--------------

Corbie reads the project's files only when they are submitted. After changing
any file, run in the project:

  corbie test .            reads every machine, and starts nothing
  corbie run submit .      records the files, and starts again what the change says

`corbie test .` names each location a machine calls that the project lacks,
and still exits 0. In a new project this is the agent.

    corbie test .
      answers.yaml                        ok
      ballot.yaml                         ok
      conversation.yaml                   ok
      grouse/slack/assistant/status.yaml  ok
      grouse/slack/chat/ask.yaml          ok
      grouse/slack/chat/post.yaml         ok
      grouse/slack/chat/show.yaml         ok
      grouse/slack/files/get.yaml         ok
      grouse/slack/grouse.yaml            ok
      later.yaml                          ok
      people/find.yaml                    ok
      .packs/                             listed
      people/scopes.yaml                  listed
      nothing in the tree is at /my-bot/agents/assistant, named by conversation.yaml states.answering.job.machine.stages.answer.job.call

Submit to one Corbie only: a second copy of a router, with the same token,
takes the first one's messages.

  a router, or a file its listener reads    the router and its listener start again; the conversations go on
  an agent, or a toolkit it includes        the next turn is answered by the new agent
  conversation.yaml                         the runs under way finish with the machines they started with
  a file deleted                            the runs at its location are cancelled
  a value                                   a listener reads it when it starts: corbie run cancel /my-bot/grouse/<service>/grouse, then submit

To update the packs, run `corbie add` in the project, with no pack named. It
adds each pack the project holds again from where it came:

1. It rewrites each pack's directory under `.packs/`.
2. It writes each starting file that is not there and that it has not written before, so a starting file you removed stays removed.
3. It adds `.packs/` to `.corbieignore` when it lacks it, and changes no other file.
4. It names the project's files that are not as the pack starts them.

A pack's starting files are the files under its `starter/` directory in
the packs' repository. Copy what you want, then run the two commands above.

What a project holds
--------------------

  .corbieignore       what is no machine: .packs/, people/scopes.yaml, and each toolkit's file
  conversation.yaml   one run for each person in each thread, and the stages of a turn
  grouse/<service>/   the router of the bot grouse on a service, and the calls it places, each a file of one line
  people/find.yaml    the lookup: who someone is, and their scopes
  people/scopes.yaml  each person's name and scopes, under their email or their ID on a service, which the pack's lookup reads
  agents/             the agent at agents/assistant, once you add it
  toolkits/<name>/    a toolkit: toolkit.yaml, its instructions, and the machines written for its tools
  schedules/          machines that run at a time, once you add one
  AGENTS.md           notes for a model or a person changing the project; it points at .packs/bot/AGENTS.md
  CLAUDE.md           makes Claude Code read AGENTS.md
  .mcp.json           starts corbie mcp for a model
  .packs/             the packs; corbie add rewrites a pack's directory, so change nothing there

A `*.yaml` that `.corbieignore` does not list has a location, `/my-bot/` and
its path without `.yaml`, as `/my-bot/agents/assistant`. A model reads
`.packs/bot/AGENTS.md` before it changes the project. Keep `.packs/` in git.

Add an agent
------------

The conversation calls the agent at `agents/assistant` for each turn, with
the asker's scopes, which the lookup reads from `people/scopes.yaml`. A
toolkit the agent includes is offered only to a person whose scopes its
`when:` names. The example's tools call GitLab, so add its pack first in the
project, and set its secret and value. In the router `corbie add` writes,
`grouse/gitlab/grouse.yaml`, give the listener's input `projects:` or
`group:`: with neither the listener fails, saying so.

    corbie add github.com/zummed/corbie-packs/gitlab --set BOT=grouse
      .packs/gitlab  github.com/zummed/corbie-packs/gitlab  <commit>
      .packs/shared  needed by gitlab  <commit>

      Wrote these starting files:

        grouse/gitlab/chat/ask.yaml
        grouse/gitlab/chat/post.yaml
        grouse/gitlab/chat/show.yaml
        grouse/gitlab/files/get.yaml
        grouse/gitlab/grouse.yaml

      Then: corbie test .

    corbie client secret set GITLAB_TOKEN --at /my-bot/grouse/gitlab
    corbie client value set GITLAB_SITE <host> --at /my-bot/grouse/gitlab

To add the agent:

1. Give each person a row in `people/scopes.yaml`, their name and scopes under their email as the service shows it, or under the service and their ID there, as `slack:U0123456789`.
2. Write `agents/assistant.yaml`, which includes `.packs/bot/agent.yaml` and names its model.
3. Write each toolkit in its own directory under `toolkits/`, list its file in `.corbieignore`, and place or write each machine its tools call.
4. Set the model's secret: `corbie client secret set ANTHROPIC_KEY --at /my-bot/agents`.

    # people/scopes.yaml, with two people
    ana@example.com: { name: Ana, scopes: [orders:read, orders:write] }
    di@example.com: { name: Di, scopes: [orders:read, orders:approve] }

    # agents/assistant.yaml
    agent: assistant
    description: Answers questions about the orders app.
    include: .packs/bot/agent.yaml
    model: { name: claude-sonnet-5-5, secret: ANTHROPIC_KEY }
    system: |
      You answer questions about the orders app. What you write is read in a
      chat: answer in a few short sentences, in everyday words.

      ${input.format}
    ask:
      machine: .packs/bot/approval.yaml
      input: { ask: [{ at: grouse/slack/chat/ask, in: "#orders-team" }], approvers: "orders:approve", within: 1d, asker: "${input.asker.email}", request: "${input.messages.map((m) => (m.later != null ? '(a reminder the bot set) ' : '') + m.text).join('\\n')}" }
    toolkits:
      orders: { include: toolkits/orders/toolkit.yaml, when: "${input.asker.scopes.includes('orders:read')}" }

    # toolkits/orders/toolkit.yaml
    description: The orders app, its settings, and changing them.
    instructions: { include: ./orders.md }
    tools:
      read_file: { call: grouse/gitlab/repository/files/read, input: { project: group/orders } }
      change_file:
        call: grouse/gitlab/repository/commits/create
        input: { project: group/orders }
        approve: true
        when: "${input.asker.scopes.includes('orders:write')}"

    # toolkits/orders/orders.md
    The orders app is built from the repository group/orders. Its settings are
    in config/app.yaml. Read a file before you change it, and change only what
    the person asked for.

    # grouse/gitlab/repository/files/read.yaml
    include: .packs/gitlab/repository/files/read.yaml

    # grouse/gitlab/repository/commits/create.yaml
    include: .packs/gitlab/repository/commits/create.yaml

    # .corbieignore, with the toolkit's file added
    .packs/
    people/scopes.yaml
    toolkits/orders/toolkit.yaml

- Ana is offered `orders` with both tools. Di is offered `orders` with `read_file` only, since she lacks `orders:write`, and her press on a question counts, since she holds `orders:approve`.
- A person `people/scopes.yaml` does not hold is answered by the agent with no toolkit, and the log of that run of `people/find` names the email and the ID it looked for: `corbie run show <id> --record`.
- The model is given `instructions:` when it opens the toolkit.
- A tool written `call:` takes its description and arguments from the machine at its location, without the names its `input:` fixes, so the model never names the project. A schedule, another machine or a client can run that machine without the agent.
- A line of `.corbieignore` is a path and takes no `*`. A machine in a toolkit's directory has the location its path gives, such as `toolkits/infra/restart`.
- A tool that uses no secret is written in place in the toolkit's file, which costs one file and one run less, and runs at the agent's location. A tool that uses a secret is a machine in the toolkit's directory, called with `call:`, with the secret set at its location or the toolkit's directory, as `--at /my-bot/toolkits/infra`, so the agent's run cannot read it.
- `change_file` waits for the agent's `ask:`, until someone with `orders:approve`, who did not ask, presses yes in `#orders-team`. A no, or no press within a day, goes back to the model as `denied`.
- Any machine at `agents/assistant` with the same input and output answers in its place, a flow with no model included, as `.packs/bot/pages/bot-design.txt` says under The agent.

Common changes
--------------

  The bot should                                    Change
  look something up, or do something, when asked    a tool in a toolkit, and a machine in its directory when it uses a secret
  let some people do more                           a toolkit's or a tool's when:, and their scopes
  ask other people about one toolkit or tool        an entry of by: in the agent's ask
  answer in one channel with other toolkits         a second agent and conversation, and a rule in the router
  answer some messages with steps of its own        a keyed statechart, and a rule in the router
  answer some messages that do not name it          overhear: true, a rule in the router, and a filter stage
  clean a reply before it is posted outside a DM    a redact stage in conversation.yaml
  do something at a time                            a schedule under schedules/
  say what it is doing while it works               the agent's system text: when to use its tool progress
  come back later to check on something             the agent's system text: when to use its tool later
  be on another service                             corbie add github.com/zummed/corbie-packs/<service> --set BOT=grouse
  be a second bot                                   corbie add each service's pack with --set BOT=<name>, and a second conversation

- To send a channel's messages to a machine of your own, such as `deploys.yaml` in `.packs/bot/pages/bot-design.txt` under Asking a person, add a rule before the conversation's in the router, and `send:deploys` to its `allow:`. Write `receive: [grouse/slack/grouse]` in your machine, so no other location starts it:

      message:
        - when: "${event.data.place === '#deploys' && !event.data.change && !event.data.unaddressed}"
          send: { to: { at: deploys, key: "${event.data.chat}" }, event: message, data: "${event.data}" }
        - when: "${!event.data.unaddressed && !event.data.change}"
          send: { to: { at: conversation, key: "${'slack:' + event.data.chat + ':' + event.data.user + ':assistant'}" }, event: message, data: "${event.data}" }

- To answer in one channel with a second agent, copy `conversation.yaml` to a file such as `team/conversation.yaml`, and change `agents/assistant` in it to `agents/team`. Write `receive: [team/conversation]` in `agents/team.yaml`, and send that channel's messages to `team/conversation` from the router, with a key that ends `:team`, and `send:team/conversation` to the router's `allow:`.
- An agent that includes `.packs/bot/agent.yaml` takes calls only from `conversation`. When a second conversation, such as a copy at `deploys.yaml`, calls the same agent, the agent writes its own `receive:` naming both, as `receive: [conversation, deploys]`, or the call is refused.
- To answer Slack messages that do not name the bot, add `input: { overhear: true }` to the router's job. A channel's message outside a thread, or a reply in a thread the bot has said something in, then comes with `unaddressed: true`, which the router's `when:` drops until you change it.
- To answer some of those, add a stage that calls a filter to the turn in `conversation.yaml`, as its comment shows, and place `.packs/bot/filters/words.yaml`, or write an agent that includes `.packs/bot/filters/model.yaml`.
- To clean a reply posted outside a direct message, add a stage that calls a redactor of your own, as the comment in `conversation.yaml` shows, and `send:redact` to the turn's `allow:`. The model still sees every tool's whole result.
- To hear every public issue and comment on GitLab or Jira, add `overhear: true` to the listener's input, and to wait until an opened issue is finished, `settle: 2m`. On GitLab, `group: <path>` reads every project of a group with one ask.
- To ask other people about one toolkit or tool, give the approval an entry of `by:` under its name. A held call of that toolkit or tool goes to the entry's `ask`, `approvers` and `within`, and every other to the approval's own:

      ask:
        machine: .packs/bot/approval.yaml
        input:
          ask: [{ at: grouse/slack/chat/ask, in: "#orders-team" }]
          approvers: "orders:approve"
          asker: "${input.asker.email}"
          by:
            infra: { ask: [{ at: grouse/slack/chat/ask, in: "#infra" }], approvers: "infra:approve", within: 1h }

- To post from a machine, call the bot's `chat/post` with `{ in, text }`, as `.packs/bot/pages/bot-design.txt` shows under The packs' calls.
- To find people somewhere else, write `people/find.yaml` as a machine of your own that takes `{ service, user, name, email }` and gives `{ name, email, scopes }`.
- To add a service, run `corbie add github.com/zummed/corbie-packs/<service> --set BOT=grouse`, set the service's secrets and values, and submit. The conversation answers every service already.
- To add a second bot, run `corbie add github.com/zummed/corbie-packs/<service> --set BOT=<bot>` for each of its services, which writes no second `conversation.yaml`. Copy `conversation.yaml` to `<bot>/conversation.yaml` and change `grouse` in it to the new bot's name, so its `receive:` names the new bot's routers. In those routers, change the `send:` target and the `allow:` entry from `conversation` to `<bot>/conversation`. Add `<bot>/conversation` to the `receive:` of each agent it calls, as `receive: [conversation, <bot>/conversation]`.

With a model
------------

The packs need no model to run, and a model can change the project for you. A
project's `.mcp.json` starts `corbie mcp --allow test` for a model that reads
it, such as Claude Code, which asks once before it starts it. Start it in the
project, and ask for what the bot should do.

The project's `AGENTS.md` names `.packs/bot/AGENTS.md`, which tells the model
how a project is changed and which pages to read. The model checks what it
writes with `corbie test`, and gives you the commands that start the bot. A
model does not run `corbie add`: you do.

The Slack app
-------------

The Slack listener needs a Slack app that is an agent and uses Socket Mode,
so nothing on the internet connects to this computer.

1. At api.slack.com/apps, choose Create New App, then From a manifest, and
   pick the workspace.
2. Choose JSON, and paste the manifest below, with your name and
   description. Slack cannot turn an agent back into a plain app.
3. Under Basic Information, App-Level Tokens, make a token with the scope
   `connections:write`, and run `corbie client secret set
   SLACK_APP_TOKEN --at /my-bot/grouse/slack`.
4. Under Install App, install the app, and set its Bot User OAuth Token with
   `corbie client secret set SLACK_TOKEN --at /my-bot/grouse/slack`.
5. In `people/scopes.yaml`, give each person's name and scopes under their
   email as Slack shows it in their profile, or under `slack:<their member
   ID>`.
6. In each channel the bot should hear, run `/invite @Grouse`.

    {
      "display_information": {
        "name": "Grouse"
      },
      "features": {
        "bot_user": {
          "display_name": "Grouse",
          "always_online": true
        },
        "app_home": {
          "messages_tab_enabled": true,
          "messages_tab_read_only_enabled": false
        },
        "agent_view": {
          "agent_description": "Answers questions and does tasks for the people it belongs to."
        }
      },
      "oauth_config": {
        "scopes": {
          "bot": [
            "assistant:write",
            "chat:write",
            "im:write",
            "channels:read",
            "groups:read",
            "im:read",
            "channels:history",
            "groups:history",
            "im:history",
            "users:read",
            "users:read.email",
            "reactions:read",
            "files:read",
            "files:write"
          ]
        }
      },
      "settings": {
        "event_subscriptions": {
          "bot_events": [
            "message.channels",
            "message.groups",
            "message.im",
            "reaction_added",
            "agent_session_stopped"
          ]
        },
        "interactivity": {
          "is_enabled": true
        },
        "socket_mode_enabled": true
      }
    }

  assistant:write                                   makes the bot an agent, which Slack gives a status and a stop button in a thread
  chat:write                                        posts, tells a person why their press does not count, and changes a question once it is answered
  im:write                                          opens a direct message to post to a person by their member ID
  channels:read, groups:read                        reads a channel's name, which a message gives as its place
  im:read                                           reads whether a conversation is a direct message, for a stop or a reaction there
  channels:history, groups:history, im:history      hears messages, and reads a thread's history
  users:read, users:read.email                      reads a sender's name and email, which the lookup finds them by
  reactions:read                                    hears an emoji added to a message, with the event reaction_added
  files:read                                        downloads the files sent with a message
  files:write                                       uploads a file with files/upload

The bot hears a direct message, and a message that names it in a channel it
was invited to. With the event `agent_session_stopped`, Slack shows a stop
button under a thread while the bot works there.
